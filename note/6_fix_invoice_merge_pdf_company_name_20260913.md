# แก้ชื่อบริษัทถูกตัดบรรทัดตอน Merge PDF — 13 กันยายน 2569

## เส้นทางที่ตรวจ

ปุ่ม `btnMergePdf` ใน form เรียก `downloadMergedPdf()` →
`POST /export-merged-pdf` → เรนเดอร์ `invoice.html` ด้วย `invoice.css`
ผ่าน WeasyPrint จำนวน 4 แบบ → รวมไฟล์ด้วย pypdf
ชื่อผู้ขายในหัวเอกสารเป็นข้อความคงที่ในแม่แบบ ไม่ได้มาจาก payload ของฟอร์ม

## หลักฐานและสาเหตุ

- ชุดทดสอบเรียก endpoint จริง ใช้ข้อมูลจำลอง และแยก `app.database` ก่อน import
  เพื่อไม่เชื่อมต่อฐานข้อมูลจริง
- โครงการไม่ได้ล็อกเวอร์ชัน WeasyPrint ใน requirements; virtualenv ที่พบมี 65.1
  ยังไม่ได้ยืนยันเวอร์ชันที่ใช้อยู่บนเซิร์ฟเวอร์จริง
- 65.1 และ 70.0 ไม่แสดงอาการก่อนแก้ แต่ 62.3 ทำให้ชื่อบริษัทถูกตัดเป็น
  `บริษัท`, `เอส`, `แอนด์`, `เอส`, `อิน`, `คอม`, `จำกัด` ในหัวเอกสารทั้ง 4 แบบ
- คำสั่ง `python tests/invoice_pdf_layout.py` ก่อนแก้บน 62.3:
  `FAILED (failures=4)`; แม้ย่อ HTML เหลือเฉพาะหัวเอกสารก็ยังเกิดอาการ
- การทดลองเปลี่ยนทีละปัจจัยบนสำเนาชั่วคราว:
  - เอา `align-self:flex-start` ของชื่อบริษัทออก: ผ่าน
  - เพิ่ม `white-space:nowrap` ให้ชื่อบริษัท: ผ่าน
  - เปลี่ยนให้ CSS และ renderer ใช้ FontConfiguration ร่วมกันอย่างเดียว: ยังไม่ผ่าน

สาเหตุที่พิสูจน์ได้คือการคำนวณความกว้างของชื่อบริษัทใน flex column ของ
WeasyPrint รุ่นเก่า เมื่อชื่อกำหนด `align-self:flex-start` และยังอนุญาตให้ตัดบรรทัด
อาการเกิดระหว่างจัดหน้า ก่อน pypdf รวมไฟล์ ไม่พบ `&#x20;` เป็นข้อความในแม่แบบ

ข้อมูลนี้สอดคล้องกับ [บันทึกการปรับปรุง Flex layout ของ WeasyPrint 65](https://www.courtbouillon.org/blog/00057-weasyprint-65/)
ซึ่งผู้พัฒนาเขียนกลไก Flex ใหม่ส่วนหนึ่งและแก้ปัญหาการจัดวางหลายกรณี

## การแก้

- เปลี่ยนหัวชื่อบริษัทเป็น `class="title company-name"` และถอด inline `align-self`
- เพิ่ม `.company-name { white-space: nowrap; }` ใน CSS ที่ใช้ร่วมกับ preview/PDF
- คงข้อความชื่อบริษัท ฟอนต์ ขนาดตัวอักษร และกระบวนการรวม PDF เดิม

## การตรวจรับ

- Native PDF บน WeasyPrint 62.3 / pydyf 0.11.0: ผ่านหลังแก้
- Native PDF บน WeasyPrint 65.1: ผ่านหลังแก้
- ทดสอบครบต้นฉบับใบกำกับ ต้นฉบับใบเสร็จ สำเนาใบกำกับ และสำเนาใบเสร็จ
- ตรวจจำนวนหน้ารวม 4 หน้า ชื่อเต็มอยู่หนึ่งบรรทัด ไม่ล้นขอบ และไม่ทับข้อความอื่น
- ตรวจภาพ PDF ก่อน/หลังจากข้อมูลทดสอบด้วยสายตา

- Chromium: ผ่านครบ 4 แบบทั้ง screen และ print media (8 กรณี)
- ชุดทดสอบ backend เดิม: ผ่าน 7 tests

ชุดทดสอบถาวร: `tests/invoice_pdf_layout.py`; วิธีรัน: `tests/README.md`
การเปลี่ยนนี้ยังไม่ได้ deploy ไปเซิร์ฟเวอร์

## ตรวจไฟล์ PDF ตัวอย่างจากผู้ใช้เพิ่มเติม

ตรวจ `invoice_merged_69090040.pdf` โดยอ่านตำแหน่งข้อความและภาพหัวเอกสาร:

- ไฟล์มี 4 หน้า A4; ทุกหน้ามี `บริษัท` ที่บรรทัดแรกและ `เอส แอนด์ เอส อินคอม จำกัด` ที่บรรทัดถัดไป
- ตำแหน่งบนของข้อความสองบรรทัดอยู่ประมาณ 46.38 และ 65.58 pt ตามลำดับ
- ทั้งสองบรรทัดใช้ฟอนต์ `TH-Sarabun-New-Bold`; ไม่มีข้อความ `&#x20;` แสดงอยู่ในหัวเอกสาร
- PDF metadata ระบุผู้สร้างเป็น `pypdf` จึงยืนยันเวอร์ชัน WeasyPrint บนเซิร์ฟเวอร์จากไฟล์นี้ไม่ได้
- ทดสอบเพิ่มเติมด้วย WeasyPrint 63.1 และ 64.1: แม่แบบเดิมตัดชื่อเป็นสองบรรทัดเช่นกัน
  แต่ตำแหน่งตัดในสภาพแวดล้อมทดสอบอยู่ก่อน `จำกัด` จึงไม่ใช่การจำลองตรงทุกตัวแปรของไฟล์ผู้ใช้
- แม่แบบและ CSS ที่แก้แล้วผ่านทั้งสองรุ่น: ชื่อเต็มอยู่บรรทัดเดียวครบ 4 แบบ ไม่ล้นหน้าและไม่ทับข้อความอื่น

ไม่ได้แก้ไข PDF ต้นฉบับใน Downloads; ต้องสร้าง PDF ใหม่หลังนำโค้ดแก้ไขไปใช้
